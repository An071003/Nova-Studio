# 09 — QA (gate & chiến lược test)

## Kim tự tháp test
| Lớp | Công cụ | Phạm vi | Ngưỡng |
|---|---|---|---|
| Unit | Vitest | shared, editor-core, api services | coverage editor-core ≥ 80%, shared 100% `can()`, api ≥ 70% |
| Convergence | Vitest + 2–3 Y.Doc nối qua `applyUpdate` (có thể random order/delay) | commands, conflict table | 100% case bảng 04-REALTIME; property test 200 thao tác ngẫu nhiên → mọi doc bằng nhau |
| API e2e | Supertest + Postgres test (docker) | mọi endpoint × role | 100% endpoint |
| Realtime integration | Vitest + Hocuspocus server thật + 2 provider (node `ws`) | auth, readOnly, persist | PASS |
| Web e2e | Playwright (chromium), 2–3 browser context = nhiều user | Eval E1–E12 | PASS, retry ≤ 1 |
| Perf | Vitest bench + script Playwright đo fps/latency | E12 | ngưỡng 00-GOAL |
| Security | checklist 07 + `pnpm audit` + gitleaks | | không high/critical |

## Quy tắc chống "giả xanh"
- Không `test.skip`, `.only`, `expect(true)`, mock thay cho thứ đang test (vd. mock Yjs khi test sync).
- Flaky test → sửa nguyên nhân (await đúng điều kiện `expect.poll`), không tăng timeout mù quáng > 2×.
- Probe output phải trích nguyên dòng tổng kết (vd. `Tests  142 passed (142)`).
